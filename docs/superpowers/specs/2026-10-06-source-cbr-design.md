# Источник курсов ЦБ РФ и слияние источников (задача 03)

Постановка: `docs-ai/planning/03-source_cbr.md`. Ветка: `feature/03-source-cbr` (от master).

## Цель
Сделать доступными RUB, BGN, HRK и другие валюты, которых нет у ЕЦБ. Для этого добавляется второй источник (ЦБ РФ), а курсы двух источников объединяются в один снимок. Domain, UI и схема Room не меняются.

## Решения (согласованы с пользователем)
- Один слитый снимок с мостом между источниками (в этой задаче).
- Приоритет при конфликте валюты задаётся в коде через enum.

## Компоненты

### 1. `CbrRateSource` и `CbrXmlParser` (`currency/data/source/cbr/`)
- Реализует `CurrencyRateSource` без изменения контракта: `id = "cbr"`, `baseCode = "RUB"`, `refreshInterval = 4.hours`.
- URL: `https://www.cbr.ru/scripts/XML_daily.asp`. Ответ читается байтами и явно декодируется в windows-1251.
- Парсер: для каждой валюты берёт `CharCode`, `Nominal`, `Value` (запятая как десятичный разделитель). Курс к RUB: `Nominal / Value`.
- Дата из атрибута `Date="dd.MM.yyyy"` приводится к формату даты `EcbXmlParser`.
- Невалидные значения (≤ 0, NaN/Infinity, нечисловые, `Nominal` ≤ 0) пропускаются; ответ без даты или без курсов — исключение (как в `EcbXmlParser`).
- Сам RUB в `rates` не входит (он база снимка).

### 2. `RateSourcePriority` (enum)
`enum class RateSourcePriority { ECB, CBR }`. Порядок констант = приоритет (первая главнее). DI строит список источников по `entries`. Перестановка констант меняет приоритет без правки логики.

### 3. `MergedCurrencyRateRepo` (`currency/data/repo/`)
Реализует `CurrencyRateRepo`. Принимает список `CurrencyRateRepo` в порядке приоритета.
- Опрашивает репозитории параллельно.
- Шкала слитого снимка — база первого успешного источника (при обоих живых это EUR), `date` — максимальная из дат.
- Для каждого следующего снимка ищется общая валюта с накопленным (предпочтительно USD, иначе любая общая). Курсы пересчитываются: `rate * accumulated[bridge] / other[bridge]` (`rate[base] = 1`, база источника тоже попадает как валюта).
- Валюта, уже присутствующая у более приоритетного источника, не перезаписывается.
- Нет общей валюты — снимок пропускается.
- Упал один источник — работаем на остальных. Упали все — пробрасывается первая ошибка. `CancellationException` пробрасывается.
- Кэш, TTL и backoff остаются в `CurrencyRateRepoImpl` каждого источника.

### 4. DI (`CurrencyModule`)
Два источника (`EcbRateSource`, `CbrRateSource`), под каждый свой `CurrencyRateRepoImpl` (разные `id` в Room), поверх них `MergedCurrencyRateRepo` в роли `CurrencyRateRepo`. Provision-методы `AppComponent` не нужны.

### 5. Откат базы
`CurrencyBaseRepoImpl.getBaseCurrency()` не меняется: `availableCodes` слитого снимка включает RUB, поэтому русская локаль выбирает RUB. Изменение подтверждается тестом.

## Тестирование (TDD)
- `CbrXmlParserTest` на фикстуре: `Nominal` (JPY, KZT и др. с номиналом > 1), запятая, windows-1251, пропуск мусора, пустой ответ, дата.
- `CbrRateSourceTest` по образцу `EcbRateSourceTest`.
- `MergedCurrencyRateRepoTest`: мост через USD, приоритет, добавление RUB/BGN/HRK, нет общей валюты, отказ одного источника, отказ всех, отмена.
- `CurrencyBaseRepoTest`: русская локаль со слитым снимком → RUB.

## Вне задачи
Источник США, привязка TTL к расписанию, нормальный текст ошибок.

## Риски
- TLS-цепочка `cbr.ru` на эмуляторе API 34 (см. `docs-ai/artifact/2026-10-06-source-data.md`) проверяется только на эмуляторе; при проблеме — отдельный шаг с промежуточным сертификатом.
- Мост даёт расхождение между датами снимков двух источников (курсы на разные дни). Принимается.
