# Источники курсов валют: контракт и реализация на ЕЦБ

Задача: `docs-ai/planning/02-source_data.md`. Ветка: `feature/source-data`.

## Цель
ExchangeRateApi перестал работать (протух ключ) и даёт узкий список валют. Заменяем его первичным источником (не агрегатором). Вводим общий контракт источника на слое Data, чтобы позже подключать другие источники. Реализуем один источник — ЕЦБ.

## Выбор источников
| Источник | Валют | База | Формат | Обновление | Статус |
|---|---|---|---|---|---|
| ЕЦБ (`eurofxref-daily.xml`) | 29 | EUR | XML | рабочие дни ~16:00 CET | **реализуем** |
| ЦБ РФ | ~55 | RUB | XML, windows-1251 | ежедневно | TODO (нужен для RUB) |
| США (ФРС H.10 / Treasury) | мало / раз в квартал | USD | — | — | TODO, контракты не изучались |

Проверено по документации ЕЦБ (2026-10-06): корень `gesmes:Envelope`, курсы в `<Cube time="YYYY-MM-DD"><Cube currency=".." rate=".."/>`, EUR в списке нет, ключа нет. ЕЦБ указывает, что курсы «для информации» и не годятся для транзакций. RUB приостановлен с 2022-03-01. BGN и HRK в файле отсутствуют.

Валюты в daily: USD JPY CZK DKK GBP HUF PLN RON SEK CHF ISK NOK TRY AUD BRL CAD CNY HKD IDR ILS INR KRW MXN MYR NZD PHP SGD THB ZAR.

## Архитектура

### Data
- `currency/data/source/CurrencyRateSource` — контракт источника:
  - `val baseCode: String`
  - `val refreshInterval: Duration`
  - `suspend fun fetch(): RateSnapshot`
- `RateSnapshot(baseCode: String, date: String, rates: Map<String, Double>)` — «1 base = rate единиц валюты». Доступные валюты = `rates.keys + baseCode`.
- `EcbRateSource(httpClient, ioDispatcher)` — запрос XML и разбор через `XmlPullParser`. Знает URL, формат и `refreshInterval` (4 ч).
- `CurrencyRateSource` дополнительно имеет `val id: String` (для ЕЦБ — `"ecb"`): ключ снимка в хранилище.
- **Персистентный кэш на Room** (новая зависимость `androidx.room`, KSP; версию берём актуальную при реализации и кладём в version catalog). Кэш переживает закрытие и краш приложения. Схема рассчитана на несколько источников:
  - `rate_snapshot(sourceId PK, baseCode, date, fetchedAt)` — один снимок на источник;
  - `rate(sourceId FK → rate_snapshot ON DELETE CASCADE, code, value)`, PK `(sourceId, code)`.
  - Сохранение снимка — одна транзакция: удалить старые строки источника, вставить новые. Читатель не увидит наполовину записанный снимок.
  - База `ratex.db`, версия схемы 1, экспорт схемы включён. Миграции пока нет; при смене схемы до релиза допустим `fallbackToDestructiveMigration`, потому что это кэш, а не пользовательские данные.
- `RateSnapshotStorage` — интерфейс в Data: `suspend fun load(sourceId): StoredSnapshot?` и `suspend fun save(sourceId, snapshot, fetchedAt)`. Реализация поверх Room DAO; репозиторий зависит от интерфейса, а не от Room, и в тестах подменяется. Room сам уводит suspend-запросы с главного потока, `withContext(ioDispatcher)` не нужен.
- `CurrencyRateRepoImpl` / `CurrencyBaseRepoImpl` — логика «память → Room → сеть»:
  1. Снимок из памяти, а если его нет — из Room (`load(source.id)`).
  2. `now − fetchedAt < refreshInterval` — отдаём без сети.
  3. Иначе `source.fetch()`, результат в память и в Room.
  4. Сеть упала, а снимок есть (любой давности) — отдаём его.
  5. Снимка нет и сети нет — исключение, UI показывает ошибку.
  - Если `baseCode` сохранённого снимка не совпадает с `source.baseCode` — снимок игнорируется, как будто кэша нет.
  - `fetchedAt` берётся по часам устройства; перевод часов может сдвинуть TTL. Для курсов раз в день приемлемо, отмечается в артефакте.
- Удаляются `ExchangeRateApi*`, `ExchangeRatesResponse`, `ExchangeRateDataStore`, `CurrencyRateDataStore`. `HttpClientModule` и `CurrencyModule` приводятся к новой схеме.

### Domain
- Интерфейсы репозиториев остаются в `domain/boundaries/repo`. Репозиторию нужен снимок, поэтому в Domain добавляется сущность снимка. Решение по форме: интерфейс `CurrencyRateRepo` отдаёт `RateSnapshotDomain` (база, дата, курсы), а не готовый список.
- Интерактор `CurrencyRateInteractorImpl` делает кросс-пересчёт чистой функцией. Для базы X (из выбора пользователя) и валюты Y:
  - X == база источника: `rate = rates[Y]`
  - Y == база источника: `rate = 1 / rates[X]`
  - иначе: `rate = rates[Y] / rates[X]`
  - Валюты Y == X в результат не входят. Y, которой нет в снимке, пропускается.
- `getAvailableCurrencies()` берёт список из снимка. Захардкоженный `arrayActualCodeCurrency` удаляется.

### Поведение при базе вне источника
Если сохранённая или локальная валюта по умолчанию отсутствует в снимке (например RUB, BGN, HRK), база берётся равной базе источника (EUR). Выбор такой валюты недоступен, потому что список валют берётся из источника. Сохранённое значение в SharedPrefs не перезаписывается.

### Пропуск валют
Код, которого нет в `java.util.Currency`, пропускается.

## Помечено в артефакте (не реализуется сейчас)
- **Мост между источниками.** Курсы разных источников связываются через общую валюту: если у источника нет курса к базе пользователя, но она есть у другого, считаем через валюту, общую для обоих (например, ЦБ РФ: RUB→USD и ЕЦБ: EUR→USD, мост по USD). Контракт уже даёт `baseCode` и состав валют каждого источника, поэтому добавление второго источника не ломает интерфейсы. Пока реализован только пересчёт внутри одного источника через его базу.
- **RUB недоступен** до подключения ЦБ РФ.
- Дисклеймер ЕЦБ: курсы информационные.

## Тесты
- `EcbRateSourceTest`: MockEngine, фикстура XML со структурой ЕЦБ; ошибки (HTTP-ошибка, битый XML).
- Тест интерактора: кросс-пересчёт во всех трёх случаях, пропуск базы и неизвестных валют.
- Тесты Room-хранилища: in-memory база на Robolectric; запись и чтение, замена снимка источника, изоляция снимков разных источников, каскадное удаление.
- Тесты репозиториев (с фейковым `RateSnapshotStorage`): свежий кэш без сети, TTL, устаревший кэш при ошибке сети, чужая `baseCode`, «процесс перезапущен» (пустая память, снимок в хранилище), откат на базу источника.
- Существующие тесты обновляются под новые сигнатуры. `./gradlew test` и `ktlintCheck` зелёные.
