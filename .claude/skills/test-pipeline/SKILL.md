# Правила работы
- Не меняй код проекта и не пиши файлы. Не запускай `ktlintFormat` и другие задачи, которые правят исходники.
- Инструментальные тесты (`connectedDebugAndroidTest`) не запускай: им нужен эмулятор.
- Не объявляй проверку успешной без её фактического результата. Секреты из вывода в результат не копируй.

# Данные на вход
- checks: List<Check>? — какие проверки запустить; `Check` = `build` | `tests` | `ktlint` | `lint`. По умолчанию все четыре.

Значение берётся из $ARGUMENTS (например, `checks: tests, ktlint`); без аргументов запускаются все проверки.

# Данные на выход
- PipelineResult по [шаблону результата](references/result-template.md): `status` (`Успех`, `Проверки не прошли` или `Ошибка окружения`) и итог по каждой проверке с причиной падения.

# Проверки
- `build` — `assembleDebug`
- `tests` — `testDebugUnitTest`
- `ktlint` — `ktlintCheck`
- `lint` — `lintDebug`

# Правила запуска
- Работай в корне проекта. Gradle не работает с Java 25 — нужен JDK 17: `JAVA_HOME=$(/usr/libexec/java_home -v 17)`; если такого JDK нет, используй путь из `CLAUDE.md`.
- Запусти выбранные задачи одной командой, чтобы Gradle отработал их все:
  `JAVA_HOME=<JDK 17> ./gradlew <задачи> --continue`
- Дождись полного завершения Gradle, даже если одна из задач упала.
- Если запуск не стартовал (нет JDK 17, нет Android SDK / `local.properties`, нет доступа к кэшу Gradle или сети), это `Ошибка окружения`, а не падение проверок.

# Правила разбора результата
- Падение задачи определяй по выводу Gradle (`FAILED`, `What went wrong`) и по отчётам в `app/build/reports` и `app/build/test-results`.
- Для каждой упавшей проверки укажи причину:
  - `build` — ошибка компиляции или конфигурации: файл, строка, сообщение;
  - `tests` — класс и метод упавшего теста, сообщение утверждения, ссылка `путь:строка` из стектрейса;
  - `ktlint` — файл, строка и правило;
  - `lint` — файл, строка, id проверки и сообщение (отчёт — `app/build/reports/lint-results-debug.txt`).
- Если одна проверка упала, остальные оцени по их фактическим результатам. Если проверка не запускалась, помечай её `[не запускалась]`, а не успешной.

# Правила формирования результата
- Заполняй [шаблон результата](references/result-template.md) целиком, порядок и названия разделов не меняй. Если в разделе нечего писать, укажи «Нет».
- Статус:
  - `Успех` — все выбранные проверки прошли;
  - `Проверки не прошли` — хотя бы одна проверка упала;
  - `Ошибка окружения` — проверки не удалось запустить.

# Алгоритм работы
1. Получи `checks`. Если не задано — все проверки.
2. Запусти выбранные проверки по [правилам запуска](#правила-запуска).
3. Разбери результат по [правилам разбора](#правила-разбора-результата).
4. Сформируй результат по [правилам](#правила-формирования-результата).
5. Верни результат своей работы.
